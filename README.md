# estimate_skills

Набор инструкций для AI-агента, который оценивает трудозатраты задач в 1С, в том числе 1С:ERP. Оценка строится по конкретным результатам работ с распределением между разработчиком, аналитиком и консультантом.

Проект содержит методику оценки и ролевые материалы в Markdown. Для подготовки оценки агенту также нужны описание задачи и доступные материалы целевой конфигурации.

## Как использовать

1. Откройте репозиторий в рабочем окружении агента либо перенесите нужные инструкции в свой проект.
2. Передайте агенту описание задачи, требования и релевантные материалы конфигурации: метаданные, код, расширения, схемы обменов и другие доступные сведения.
3. Попросите применить общий скилл `estimate-task` и ролевые материалы по фактическим путям из таблицы выше.
4. Проверьте основания расчёта, допущения, исключения и вопросы перед согласованием оценки.

При переносе в другой проект согласуйте пути к скиллам в `AGENTS.md` со структурой этого проекта.

### Пример запроса

```text
Оцени трудозатраты на доработку 1С:ERP.

Задача: добавить в существующий отчёт по заказам клиентов отбор
по ответственному и вывод суммы просроченной задолженности.

Материалы: описание отчёта, его СКД и сведения об источнике задолженности
приложены к запросу.

Используй .agents/skills/estimate-task/SKILL.md и применимые
ролевые материалы из .agents/skills/.

Раздели работы по результатам и исполнителям. Для каждой работы
укажи основание оценки, часы и размер. Покажи итог по ролям и размер
всей задачи, допущения, исключения и вопросы, которые могут изменить оценку.
Если данных недостаточно, отдельно оцени этап уточнения.
```

## Как строится оценка

- Сначала определяются цель, границы задачи и ожидаемые результаты.
- Работы распределяются между ролями по их содержанию. Часы каждой роли добавляются только при наличии необходимой работы.
- Для разработки выбираются элементы каталога, сложность и подтверждённые коэффициенты. Базовый норматив рассчитан на разработчика уровня Middle и включает уточнение постановки, разработку, первичное тестирование и краткое техническое описание.
- Работы, уже включённые в норматив, повторно не учитываются.
- При нехватке данных фиксируются допущения и вопросы; предварительная оценка сопровождается объяснением диапазона.
- Итог выражается в человеко-часах. Для перевода в календарный срок нужны сведения о составе и доступности команды.

Нормативы ролевых скиллов нельзя менять без явного основания. Если применимого норматива нет, число должно быть обозначено как экспертное допущение либо работа должна остаться на уточнение.

## Ожидаемый результат

Оценка включает понимание задачи, изученные материалы и таблицу работ:

| Результат / работа | Роль | Основание оценки | Объём | Часы | Размер |
|---|---|---|---|---|---|
| Конкретный результат | Исполнитель | Норматив или экспертное допущение | Количество | Расчёт | По часам строки |

Столбец «Размер» обязателен и в сокращённой оценке. Используется шкала XS/S/M/L/XL/Epic из скилла разработчика. Размер строки определяется по её часам, итог по роли — по часам роли, размер всей задачи — по сумме часов всех участвующих ролей. В таблице итогов также указываются размеры, включая строку «Всего». При пересечении категорий диапазоном часов выводится диапазон размеров, например L–XL; без численной оценки — «На уточнении». Правила граничных значений заданы в скилле разработчика.

После декомпозиции приводятся итоги по ролям и общая сумма, существенные допущения, исключённые работы и вопросы для уточнения. Взаимоисключающие варианты реализации оцениваются отдельно.

## Текущее состояние

- Общая методика оценки и скилл разработчика содержат инструкции для расчёта.
- Материал аналитика описывает роль, но завершается незаконченной строкой о нормативе: `Каждая задача аналитика оценивается в 8 человеко-`. Применимость и единицу этого норматива нужно уточнить перед использованием.
- Файл консультанта ERP пока пуст, поэтому нормативов консультационной работы в репозитории нет.

Эти пробелы следует учитывать в оценках: основания и допущения по соответствующим работам должны быть указаны явно.
