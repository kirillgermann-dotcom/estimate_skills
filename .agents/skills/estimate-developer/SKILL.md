# Трудооценка разработки на 1С

## Назначение и границы

Оценивай работу разработчика 1С уровня Middle. Базовый норматив включает уточнение постановки, разработку, первичное тестирование и краткое техническое описание. По умолчанию не включает ожидание согласований, приемочное тестирование заказчиком и промышленное внедрение.

## Обязательный алгоритм

1. Извлеки цель, результат, объекты метаданных, регистры, формы, запросы, права, интеграции, объем данных, тип конфигурации и способ доработки.
2. Раздели составную задачу на элементы каталога. Отчет, движения, права, миграция, интеграция и отдельное проектирование оцениваются раздельно, если это самостоятельные работы.
3. Для каждого элемента выбери код и сложность: простая, средняя или сложная.
4. Возьми базовые часы из каталога.
5. Примени только подтвержденные коэффициенты к тем элементам, которых они касаются.
6. Сложи элементы, определи размер задачи и минимальную компетенцию.
7. Проверь двойной учет, допущения, исключения и необходимость декомпозиции.

Не складывай дублирующие работы. Например, не добавляй стандартную форму отдельно, если она уже полностью покрывается разработкой объекта. Если сведений мало, сначала дай предварительный диапазон на явных допущениях, затем задай не более 7 вопросов, способных существенно изменить оценку. Не переводи часы в календарные сроки без данных о составе и доступности команды.

## Расчет

Для каждого элемента:

`T = T_база × K_конфигурации × K_данных × K_интеграции × K_прочие`

Итог: `T_итого = ΣT_i`. Не округляй промежуточные значения. Итог округляй до 0.5 часа, а свыше 40 часов допустимо до целого часа. Если коэффициенты заданы диапазонами, покажи нижнюю, ожидаемую и верхнюю оценки и объясни выбранные значения. Не учитывай один риск несколькими коэффициентами.

## Формат ответа

### Краткий вывод

Укажи ожидаемые часы, диапазон, размер, минимальную компетенцию и необходимость декомпозиции.

### Декомпозиция

| № | Код | Элемент | Сложность | База, ч | Коэффициенты | Итого, ч | Размер | Компетенция |
|---:|---|---|---|---:|---|---:|---|---|

Столбец «Размер» обязателен, в том числе в сокращённой оценке. Для каждого элемента определяй размер по его итоговым часам после коэффициентов. Добавляй итоговую строку «Всего» с суммой часов и размером всей задачи разработки; размеры элементов не складывай.

### Расчет

Покажи формулы элементов и сумму.

### Допущения и риски

Укажи только факторы, влияющие на часы или компетенцию.

### Что не входит

Перечисли исключенные работы.

### Уточняющие вопросы

Добавляй раздел только при нехватке существенных данных.

## Размер итоговой задачи

| Размер | Часы | Описание |
|---|---:|---|
| XS | 0.5–2 | Точечное изменение |
| S | 2–8 | Один объект, типовой алгоритм |
| M | 8–24 | Несколько объектов, запросы, проверки или движения |
| L | 24–60 | Несколько подсистем, сложные алгоритмы, права или обмены |
| XL | 60–120 | Архитектурные изменения, интеграции, многорегистровый учет |
| Epic | >120 | Обязательна декомпозиция |

`Простая/Средняя/Сложная` — сложность элемента каталога; `XS/S/M/L/XL/Epic` — размер результата. Элементы свыше 60–80 часов желательно декомпозировать.

На общей границе интервалов выбирай меньший размер: 2 ч → XS, 8 ч → S, 24 ч → M, 60 ч → L, 120 ч → XL. Положительные оценки менее 0.5 ч относи к XS; для строки с нулём часов указывай «Не применимо».

Размер определяй по тому же итоговому значению часов, которое выводишь в строке. Для диапазона часов классифицируй обе границы: если категории различаются, укажи диапазон размеров, например L–XL; иначе укажи одну категорию. Если численной оценки нет, пиши «На уточнении».

## Критерии сложности

| Параметр | Простая | Средняя | Сложная |
|---|---|---|---|
| Метаданные | 1 объект | 2–5 объектов | >5 объектов |
| Регистры | Один существующий | 1–3 | Несколько взаимосвязанных |
| Запросы | Одна таблица | Соединения, группировки | Временные таблицы, пакеты, сложные расчеты |
| Формы | Стандартная | Динамическая | Сложное рабочее место |
| Интеграции | Нет | Один стабильный интерфейс | Несколько систем или нестабильный API |
| Права | Типовые роли | Несколько ролей | RLS/разделение данных |
| Данные | Объем не влияет | Пакетная обработка | Оптимизация и контроль блокировок |
| Требования | Определены | Нужны уточнения | Нужны исследование и проектирование |
| Конфигурация | Собственная | Типовая с расширением | Сильно измененная/устаревшая |

# Компетенции

| Код | Уровень | Основные требования |
|---|---|---|
| J | Младший | Базовый код, простые запросы/СКД, типовые обновления |
| M | Разработчик | БСП, временные таблицы, вложенные запросы, внешние обработки |
| S | Ведущий | Проектирование, сложная СКД, библиотеки, HTTP-сервисы, проектные базы |
| A | Архитектор | Архитектура, СУБД, производительность, интеграции, code review |

Базово: XS/S → J; M → M; L → S; XL → S с архитектурным контролем либо A; Epic → A и декомпозиция.

## Повышение компетенции

Повысь уровень на одну ступень, не выше A, если присутствует хотя бы одно условие: несколько подсистем; многорегистровые движения; RLS; внешняя система; большие данные; требования по производительности/блокировкам; сильно измененная типовая конфигурация; нет документации; архитектурное проектирование; риск повреждения учетных данных. Несколько условий не означают автоматического повышения на несколько ступеней; дополнительное повышение требует объяснения.

Для составной задачи бери максимальный уровень элементов. Исполнитель на ступень ниже может делать отдельные подзадачи, но проектирование, приемка и code review выполняются на требуемом уровне. Для миграции и исправления продуктивных данных проверь наличие резервной копии, протоколирования, сверки и отката. Для RLS включи проверку производительности и изоляции данных.

# Финальная самопроверка

Перед ответом убедись, что:

- все существенные работы классифицированы и не задвоены;
- сложность обоснована признаками;
- коэффициенты локальны и объяснены;
- диапазон не выдан без допущений;
- столбец «Размер» присутствует и заполнен для всех элементов и строки «Всего», соответствует их итоговым часам, границам шкалы и диапазону оценки;
- компетенция учитывает специальную матрицу;
- явно указано, что не входит;
- Epic и крупные элементы декомпозированы либо отмечены для декомпозиции.
